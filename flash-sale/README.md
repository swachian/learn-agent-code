# 秒杀系统设计

## 1. 架构设计

### 整体架构
```
                    ┌─────────────────────────────────────────┐
                    │                  CDN                     │
                    └─────────────────────────────────────────┘
                                        │
                    ┌─────────────────────────────────────────┐
                    │              LVS/Nginx                  │
                    │           (负载均衡+限流)                │
                    └─────────────────────────────────────────┘
                                        │
                    ┌─────────────────────────────────────────┐
                    │         API Gateway (限流/鉴权)         │
                    └─────────────────────────────────────────┘
                                        │
                    ┌─────────────────────────────────────────┐
                    │           消息队列 Kafka               │
                    │         (异步下单, 削峰填谷)            │
                    └─────────────────────────────────────────┘
                                        │
                    ┌─────────────────────────────────────────┐
                    │        秒杀服务集群 (多节点)            │
                    └─────────────────────────────────────────┘
                          │                    │
               ┌──────────┴──┐        ┌───────┴────────┐
               │   Redis     │        │    MySQL       │
               │  (库存缓存)  │        │   (订单数据)   │
               └─────────────┘        └────────────────┘
```

### 核心设计要点

1. **Redis 预扣减库存** - 解决高并发下的数据库压力
2. **Kafka 异步下单** - 削峰填谷，将峰值请求平滑处理
3. **Lua 脚本原子操作** - 保证库存扣减原子性
4. **乐观锁/分布式锁** - 最终一致性保障
5. **库存多级缓存** - 本地缓存 + Redis 缓存

## 2. 技术选型

- **Web框架**: Gin (高性能)
- **缓存**: Redis Cluster
- **消息队列**: Kafka
- **数据库**: MySQL (支持读写分离)
- **限流**: 令牌桶/滑动窗口

## 3. 核心流程

```
用户请求 → 限流检查 → 缓存检查库存 → Redis预扣库存 → 发MQ消息 → 返回排队中
                                    ↓
                         消费者处理 → 落库 → 更新状态
```

## 4. 关键问题解决方案

### Q1: 超卖问题
- Redis Lua 脚本保证原子性扣减
- 数据库乐观锁 (version) 做最终校验

### Q2: 100万TPS性能
- Redis 集群分片，库存分桶
- Kafka 多分区并行消费
- 本地热点缓存

### Q3: 一致性问题
- 异步消息保证最终一致
- 对账系统处理异常

## 5. 性能估算

- Redis 单机 QPS: ~10万
- 100台 Redis 集群: 1000万 TPS
- Kafka 单机: ~10万/分区
- 10台消费者集群: 100万 TPS 处理能力
